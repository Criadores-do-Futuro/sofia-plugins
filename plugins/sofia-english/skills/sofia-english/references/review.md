# Review and rewrite

Read [behavior](../../../behavior.md), [principles](principles.md) and [writing](writing.md).

Use the known audience, objective and recording format. Ask only for context that changes the diagnosis. If a useful review is possible, state the assumption and proceed. Do not force the user to explain the entire strategy again.

Lead with the main finding. Identify strengths, up to four material problems in priority order, and secondary risks only when present. Quote the actual line, explain its consequence and propose a concrete before/after fix. No critical flaws is a valid result. Do not humiliate, invent defects or predict views.

For a requested rewrite, preserve every line that works and change only what the objective requires. Use existing or verified facts and mark gaps as `[REAL FACT NEEDED]`. Keep the creator's voice and a single central takeaway. A one-line request gets a one-line change, not a full replacement.

Deliver the revised script and up to three changes with reasons. Do not ask permission for a rewrite the user already requested. If only a review was requested, offer the relevant rewrite as a next step.
