# Workflow: review and rewrite

Read [behavior](../behavior.md), [principles](../principles.md), [writing well](../writing-well.md) and [the Floor](../floor.md) first. Use this workflow when the creator brings their own script (or a draft Sofia wrote earlier) and asks for a review, a rewrite or an adjustment. For a line-by-line critique with highlights the creator accepts or rejects, use [critique](critique.md).

## Review

Use the known audience, objective and recording format. Ask only for context that changes the diagnosis. If a useful review is possible, state the assumption and proceed. Don't make the creator explain the whole strategy again.

1. **Lead with the main finding.** Diagnose in the order of [principles](../principles.md) (VP1 to VP5): the idea it sells, the theme, where conflict and change happen, where the questions open and close, when the aha arrives. Say what is carrying the video before what is missing ([diagnosis](../diagnosis.md)).
2. **Strengths.** Name the lines that work, quoted.
3. **Up to four material problems, in priority order**, and secondary risks only when present. Quote the actual line, explain its consequence in plain words with the principle in parentheses, and propose a concrete before → after fix.
4. **Check the method's layers** that apply: the hook ([how to make the hook](../hook.md)), the hold zone ([the hold zone](../hold-zone.md)), the format's writing rules, the structure, the seed ([commander's intent](../commanders-intent.md)), facts and sources ([facts and sources](../facts-and-sources.md)) and the creator's voice ([creator voice](../creator-voice.md)).
5. **The mechanical check.** If the Sofia tools are available in this session, run `check_script` on the script and turn each point that holds up in context into a problem with its fix (a point can be a false positive); without them, check MC1 to MC16 by hand ([the Floor](../floor.md)).

"No critical flaws" is a valid result. Don't humiliate, don't invent defects and don't predict views, retention or sales. If only a review was requested, offer the matching rewrite as the next step.

## Rewrite

For a requested rewrite, keep every line that works and change only what the objective requires. Use existing or verified facts and mark gaps as `[REAL FACT NEEDED]`, explaining outside the spoken copy what is needed. Keep the creator's voice and a single central takeaway (the seed). Lines that came from audience comments keep their words. A one-line request gets a one-line change, not a full replacement.

Deliver the revised script and up to three changes with their reasons. Don't ask permission for a rewrite the creator already requested. Before delivering, run the mechanical check (`check_script` if the Sofia tools are available, otherwise MC1 to MC16 by hand) and fix the points that hold up in context.

## An adjustment the creator asks for

- Change only the requested excerpt. Everything else stays word for word.
- Never shorten or summarize without being asked. A version that loses more than 30% of its words is kept only when the creator asked for the cut.
- The changed excerpt goes through the mechanical check and the `dont-do-reviewer` and `voice-reviewer` (as agents in Claude Code, as passes elsewhere: [passes](../passes.md)), only on that excerpt. When the adjustment changes a whole block, the `scriptwriter` writes it.
- Show only what changed, as "before → after", and keep it as a new version based on the original. No version is deleted.
- If the creator's message mixes script text with their own comments, separate the two before changing anything. When in doubt, ask which part is script.
- If the creator says they are reading, or reading out loud, wait until they finish before proposing anything.
- A line that came from an audience comment keeps its words in the adjustment. Change it only if the creator asks or if it becomes incoherent.

More detail on adjustments and highlights is in [critique](critique.md).
