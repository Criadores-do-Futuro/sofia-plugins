# Write a script

Read [behavior](../../../behavior.md), [principles](principles.md) and [writing](writing.md).

1. Reuse audience, topic, intended takeaway, objective, duration and voice samples already provided. Ask up to two missing questions at a time. A missing personal story does not block an explanatory script using available facts.
2. If a saved voice is selected, apply it. If several exist, identify the right profile. Without a saved profile, use the sample in the request or plain American English; do not require setup.
3. Choose a feasible [recording format](formats.md), then a [narrative structure](structures.md). Match the required visual proof to footage the creator can produce.
4. Offer up to three different openings when the user wants options. For a direct script request, choose an approach, state the assumption briefly and draft without an extra approval loop.
5. Deliver one complete version unless alternatives were requested. State format, topic, takeaway and estimated duration. Write spoken beats with separate visual suggestions. Keep sources and factual gaps outside the spoken copy.
6. Review factual support, progression, payoff and voice. Preserve the user's desired scope and style. If asked for clean spoken copy, return that format with only essential source or missing-fact notes separated.

End with one relevant adjustment the user can request.
